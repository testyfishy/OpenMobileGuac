# Feature audit

Audit of commit `5f2df8d` (the `main` tip on 2026-11-20). Changes made in the working tree
after that commit were not audited.

**Method**

- **Browser:** each flow was run in a clean worktree at that commit, in Chromium at phone size
  (375 × 812, device pixel ratio 2) and in landscape (812 × 375). Three back ends were used:
  - the built-in Demo server;
  - the dev harness (`ui/session/dev/harness.html`, plain and `?tunnel=features`);
  - a throwaway mock of the Guacamole 1.6.0 REST API (sign-in, TOTP and TOTP enrolment,
    token check, session delete, a connection tree, share keys). It ran on loopback and was
    not committed.
- **Instrumentation:** what reached the Demo server was recorded by wrapping
  `DemoServer.prototype.receive` from the page. Gestures used synthetic touch, mouse and
  stylus Pointer Events; keys used KeyboardEvent, InputEvent and CompositionEvent.
- **Code review:** the source was checked against the vendored `guacamole-common-js` and
  against guacamole-client and guacamole-server at tag 1.6.0 (fetched with `gh api`). Three
  independent review passes (core/security, input, session lifecycle) were cross-checked.
  Findings that came only from reading code are marked **code-read**.

**Verdicts**

- **PASS:** seen working in the browser.
- **PASS-CODE:** logic checked by reading and tests, but not exercisable in a desktop
  browser; the device or server test it needs is named.
- **FAIL:** reproducible bug.
- **RISK:** works, but is fragile or wrong in a case that is described.

**Severity:** S1 security or data loss, S2 feature broken, S3 degraded, S4 cosmetic, wording
or accessibility.

## 1. Summary

**Checks:** `npm run check` passes (typecheck, lint, format, 44 files / 840 tests, build).
`npm audit --omit=dev` reports 0 vulnerabilities. The production build boots under
`vite preview`, and the Demo session works with no console errors. The only console message
was a `navigator.vibrate` block before the first user tap.

**Verdict counts** (115 rows in §2; each row is counted under its worst verdict,
FAIL > RISK > PASS-CODE > PASS):

## 3. Security and privacy

**Where secrets live**

- **Passwords, tokens and TOTP seeds** are in `SecureStore` only:
  - native: Keychain / Keystore via `@aparajita/capacitor-secure-storage`, `whenUnlockedThisDeviceOnly`;
  - production web: memory;
  - dev web: localStorage under `omg-insecure-dev-secret:`, with a visible warning.
- **Profiles, settings, recents, favourites and thumbnails** are in Preferences (localStorage on
  the web).
- **No secret reached the console or the diagnostics log** in the flows above. The plain
  backup has no secrets; the encrypted part uses PBKDF2-SHA256 (310 000) and AES-256-GCM with
  a fresh salt and IV. Tokens are never exported.

on the remote machine has no Guacamole equivalent.

### 4.3 What the client can influence at connect time (verified in 1.6.0 source)

**Only `GUAC_*` values are read from the tunnel request.** `TunnelRequest.java` (lines 43–100)
defines `GUAC_DATA_SOURCE`, `GUAC_TYPE`, `GUAC_ID`, `GUAC_WIDTH`, `GUAC_HEIGHT`, `GUAC_DPI`,
`GUAC_AUDIO`, `GUAC_VIDEO`, `GUAC_IMAGE` and `GUAC_TIMEZONE`. `TunnelRequestService.java`
(132–171) copies only those into `GuacamoleClientInformation`.

**Connection parameters come only from the stored configuration.**
`ConfiguredGuacamoleSocket.java:251` reads them with `config.getParameter`. Parameter tokens
are filled by the server.

- A normal user cannot set `color-depth`, `force-lossless`, `enable-wallpaper`, `disable-gfx`,
  `resize-method`, `enable-audio`, or VNC `quality-level` / `compress-level` / `encodings` for
  a session.
- Changing them means editing the connection through the REST API, which needs UPDATE
  permission and changes it for every user. Parameter names were checked in guacd
  `rdp/settings.c` and `vnc/settings.c`, and at
  https://guacamole.apache.org/doc/1.6.0/gug/configuring-guacamole.html.
- Mid-session `argv`: RDP and VNC accept only `username` / `password` (/ `domain`). SSH accepts
  `color-scheme`, `font-name` and `font-size`.

**Image formats**

- Only WebP is negotiable: guacd checks for `image/webp` (`libguac/user.c:337-355`,
  `client.c:1063-1071`), and every connected user must support it.
- JPEG and PNG are sent whatever the client advertises (`client.c:788-823` does not check).
  Dropping `image/png` or `image/jpeg` from `GUAC_IMAGE` therefore changes nothing.
- The encoder is WebP, then JPEG (opaque layers only), otherwise PNG
  (`display-worker.c:349-363`).
- Lossy encoding is used only for regions updating at 3 fps or more, never with
  `force-lossless` (`display-plan.h:77,83`, `display-worker.c:237-285`).
- Lossy quality is `90 − (lag − 20)`, clamped to 30–90, from the client's `sync` lag
  (`display-worker.c:128-143`). The client cannot choose it.

**Audio**

- Encoders are assigned only for the advertised `GUAC_AUDIO` types (`libguac/audio.c:75-107`).
- With none advertised, `guac_audio_stream_write_pcm` sends nothing (`audio.c:206-212`).
- The app currently always advertises `audio/L8` and `audio/L16` (seen in the tunnel query).

**Size and DPI decide the RDP desktop size,** when the admin has not fixed `width`, `height`
or `dpi`.

- guacd picks 96 DPI if `W·96/dpi × H·96/dpi ≥ 800×600` (an area check), else 120 DPI if that
  passes, else the client's DPI (`rdp/resolution.c`). The desktop is then `W·res/dpi` ×
  `H·res/dpi`, with the width rounded down to a multiple of 4 (`rdp/settings.c:851-877`).
- The app sends `W·dpr × H·dpr` at `96·dpr` (`core/api/tunnel.ts:74-85`), as the upstream web
  client does.
- VNC ignores the requested size.

### 4.4 Proposed "Quality" setting

Per server, overridable per connection, applied at connect, so changing it reconnects. Each
level uses only mechanisms verified above. It has no effect where the admin has fixed `width`,
`height` or `dpi`; size has no effect on VNC.

| Level              | `GUAC_WIDTH` / `GUAC_HEIGHT` / `GUAC_DPI`                                                                                                                                                                                                                                                                                                                   | `GUAC_IMAGE`                                                                                      | `GUAC_AUDIO`                                                                                           | Other                                                                                                                                                                                                      |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Auto** (default) | As today: `W·dpr`, `H·dpr`, `96·dpr` (upstream behaviour).                                                                                                                                                                                                                                                                                                  | `image/jpeg`, `image/png`, plus `image/webp` if the WebView decodes it (as today).                | Supported types, unless the separate "Audio" switch is off.                                            | —                                                                                                                                                                                                          |
| **Best quality**   | Device pixels, with DPI raised just enough that guacd's 96 and 120 DPI candidates both fall below the 800×600 area. Then the desktop is native resolution: DPI = `max(96·dpr, ⌈120·√(W·H / 480000)⌉ + 1)`. For 1170 × 2532 that is DPI 299 → 1168 × 2532 at about 311 % scaling, instead of 484 × 1055. For 750 × 1624 the result equals today's (DPI 192). | As Auto.                                                                                          | As Auto.                                                                                               | Hint: true lossless needs the admin to set `force-lossless=true` and `color-depth=24`; the client cannot force either.                                                                                     |
| **Low bandwidth**  | CSS pixels at 96 DPI: 375 × 812 → 375 × 812 @ 96 (0.30 MP); 390 × 844 → 388 × 844 @ 96 (0.33 MP). guacd accepts these because the DPI equals the client's own. Optionally cap the long edge (for example 1280).                                                                                                                                             | Keep `image/webp`: guacd can use it on non-opaque layers too and it is usually smaller than JPEG. | **None advertised**, so guacd sends no audio data (saves about 1.4 Mbit/s compared with a local mute). | No mid-session `size` updates (match-device-size off). Text-only hint listing the admin-side switches: `color-depth=16`, `disable-gfx`, wallpaper and theming off, VNC `quality-level` / `compress-level`. |

A separate **Audio on/off** switch should map to advertising no `GUAC_AUDIO` types, not to a
local mute.

The UI or docs should say what the client cannot control: JPEG/WebP quality, frame rate,
colour depth, and the choice between JPEG and PNG.

## 5. Still needs a physical phone or a real Guacamole server (in this order)

1. **iPhone + real RDP server, sign-in and sharpness.**
   - Session info › Remote resolution on a DPR-3 iPhone (issue 9).
   - Real soft keyboard: typing, Backspace, autocorrect, a Japanese IME, swipe typing, iOS
     space-bar caret.
   - Paste button and the iOS paste prompt.
2. **Background behaviour on iOS and Android.** Background for 20 s and 70 s, then return
   (issue 8, guacd's 15 s timeout), with keep-awake and audio running.
3. **Admin actions on a real server.** Kill from Active Sessions (issue 7); RDP log-off and
   idle timeout end reasons; reconnect after a network change (Wi-Fi ↔ cellular).
4. **App lock on device.** Cold start, deep link while locked, biometric error, passcode
   removed (issue 3); privacy screen in the app switcher.
5. **TLS.** An https server with an untrusted or private-CA certificate, with and without the CA
   installed (error text on iOS and Android; silent http fallback, issue 11).
6. **Files and printing on real RDP drive and SFTP.**
   - Large download and upload, then cancel.
   - Print a test page to the share sheet.
   - Downloads disabled.
7. **Audio.** Playback, mute, the iOS silent switch, an incoming call, and audio after
   returning from the background.
8. **Hardware input on iPad / DeX / Bluetooth.** Cmd mapping, pointer lock, wheel, stylus.
   Also three-finger gestures on iOS, which may be taken by the system's undo/redo or Zoom.
9. **RDP with touch enabled.** Touch pass-through and panning when zoomed.
10. **Deep links and share links.** Cold and warm start of a deep link on both OSes (whether
    it fires twice); a real share link landing on the shared connection.
11. **SSO.** In-app browser with a real IdP; app-callback with a second app claiming the scheme.
12. **Accessibility and backup.** VoiceOver and TalkBack pass, including the screens behind a
    session (issue 10) and large text. Android backup/restore of app data and Keychain
    behaviour after an iOS restore.
